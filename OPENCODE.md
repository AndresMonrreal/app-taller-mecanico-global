## What this project is

ULLOA is a highly scalable automotive workshop management platform consisting of two independent packages:

| Package               | Description                                                     |
| --------------------- | --------------------------------------------------------------- |
| `taller-mecanico-api/` | FastAPI + SQLAlchemy (Oracle Autonomous DB) REST API            |
| `auto-hub-pro/`        | React 19 + TanStack Router + TanStack Query + shadcn/ui frontend |

Each package has its own agent definitions in `.ai/agents/` with package-specific conventions. **Ensure the relevant agent is loaded before working in that package.**

## Monorepo structure

This is **not** a workspace monorepo — the two packages are fully independent. There is no root `package.json`. Always `cd` into the target package directory before running any commands.

## Git structure

Each sub-package is its own git repository. The monorepo root is a separate repository. Ensure feature branches are created across all affected repos with the exact same name.

## How the packages relate

- `taller-mecanico-api` exposes `/api/v1` endpoints consumed by `auto-hub-pro`
- The frontend uses `VITE_API_URL` (set in `auto-hub-pro/.env`) to point at the API.
- Auth: JWT Bearer tokens with bitmask permissions are managed via `app/auth/jwt.py` and stored in `localStorage`.

## Feature development workflow

Features follow a three-step pipeline using custom slash commands at the monorepo root:

| Command                | Purpose                                                                                |
| ---------------------- | -------------------------------------------------------------------------------------- |
| `/spec <idea>`         | Creates `.ai/specs/<slug>.md` and switches all affected repos to a new feature branch  |
| `/plan-spec <slug>`    | Reads a spec and produces a detailed implementation plan saved to `.ai/plans/<slug>.md` |
| `/execute-plan <slug>` | Reads a plan and fully implements it using agents, skills, and direct edits            |

*Note: Even if the user does not use a slash command for a quick fix, the "No Excuses" protocol still applies.*

## Oracle persistence error guard

**Before writing any Alembic migration, SQLAlchemy model, or raw SQL query**, verify the following Oracle-specific rules:

- Use `VARCHAR2(n)` instead of `VARCHAR`.
- Use `NUMBER(p,s)` for decimal columns, never `FLOAT` or `REAL`.
- Use `TIMESTAMP` instead of `DATETIME`.
- Identity columns use `GENERATED BY DEFAULT AS IDENTITY`.
- Use bind variables (`:param`) in raw SQL, never f-string interpolation.

*If `.ai/persistence/errors.md` exists, consult it alongside `.ai/persistence/lessons-learned.md`.*

## Frontend visual validation (Playwright MCP)

After making any UI change to `auto-hub-pro`, use the Playwright MCP server to validate that the affected interface renders correctly.

**Required viewports:**
- Desktop: 1280 × 800
- Mobile: 390 × 844

**Validation steps:**
1. Ensure the dev server is running (`cd auto-hub-pro && bun run dev`).
2. Use `mcp__playwright__browser_navigate` to open the affected page.
3. Use `mcp__playwright__browser_resize` for each size.
4. Use `mcp__playwright__browser_take_screenshot` to capture the result.
5. Visually inspect for layout breaks, overflow, or clipping.
