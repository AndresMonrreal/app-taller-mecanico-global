# Spec: Maximizar calificación rúbrica
**Fecha:** 2026-05-12
**Slug:** maximizar-calificacion-rubrica
**Paquetes afectados:** taller-mecanico-api, auto-hub-pro
**Branch:** opencode/feature/maximizar-calificacion-rubrica

## Resumen ejecutivo
Implementar la totalidad de los objetos faltantes identificados en la auditoría de rúbrica para obtener puntuación máxima en las 13 categorías. Esto incluye: corrección del modelo relacional existente (columnas mal nombradas), creación de todos los objetos PL/SQL (procedimiento almacenado con transacción explícita, función escalar, compound trigger, vistas simples y complejas, vista materializada), sistema de roles y permisos con bitmask hexadecimal directamente en Oracle con función de validación, constraints e índices faltantes (CHECK, UNIQUE compuesto, índice compuesto, índice funcional), trigger que asigna ses_id automáticamente, seed data de prueba, SAVEPOINT en operaciones críticas, usuario de BD con privilegios mínimos, corrección de bugs en frontend (interceptor JWT en axios, tipos incorrectos), y migración UUID opcional en los modelos.

## Diseño técnico

### Base de datos (Oracle 23ai)

#### Correcciones al modelo existente
- **Vehicle.cli_date_mod** → renombrar a `veh_date_mod`
- **Alembic migration**: alinear `srv_price` → `srv_price_hour` y `ord_urgency` NOT NULL → nullable
- **UNIQUE compuesto**: `ServiceOrders(ord_id, srv_id)` vía `__table_args__`
- **CHECK constraints**: `veh_year > 1900`, `ords_hours > 0`, `ord_status IN ('ABIERTA','EN_PROCESO','CERRADA')`
- **Índice compuesto**: `idx_ordenes_status_fecha` sobre `(ord_status, ord_date)`
- **Índice funcional**: `idx_vehiculo_upper_plate` sobre `UPPER(veh_plate)`
- **UUID**: agregar columna `uuid` tipo `RAW(16)` con GENERATED BY DEFAULT AS IDENTITY o SYS_GUID() en cada tabla (opcional, baja prioridad)

#### Tablas nuevas
- **permisos_rol**: `rol_id`, `rol_nombre`, `permiso_bitmask NUMBER(3)` — máscara hexadecimal para cada rol
- **permisos_recurso**: `recurso_id`, `recurso_nombre`, `permiso_requerido NUMBER(3)` — mapeo endpoint → bitmask

#### Vistas
1. **vw_resumen_clientes** (compleja — JOIN + subconsulta):
   ```sql
   SELECT c.cli_id, c.cli_name,
          (SELECT COUNT(*) FROM Vehicles v WHERE v.cli_id = c.cli_id) total_vehiculos,
          COUNT(o.ord_id) total_ordenes,
          SUM(CASE WHEN o.ord_status = 'CERRADA' THEN 1 ELSE 0 END) ordenes_cerradas
   FROM Clients c
   LEFT JOIN Orders o ON o.veh_id IN (SELECT veh_id FROM Vehicles v2 WHERE v2.cli_id = c.cli_id)
   GROUP BY c.cli_id, c.cli_name
   ```
2. **vw_ordenes_activas** (simple — filtro WHERE):
   ```sql
   SELECT ord_id, veh_id, ord_status, ord_date, ord_urgency
   FROM Orders WHERE ord_status IN ('ABIERTA','EN_PROCESO')
   ```
3. **v_materializada_metricas_taller** (vista materializada):
   ```sql
   CREATE MATERIALIZED VIEW vm_metricas_taller AS
   SELECT TRUNC(ord_date) dia, COUNT(*) total_ordenes,
          SUM(CASE WHEN ord_status = 'CERRADA' THEN 1 ELSE 0 END) cerradas
   FROM Orders GROUP BY TRUNC(ord_date)
   ```

#### Procedimiento almacenado
- **sp_cerrar_orden**(p_ord_id IN NUMBER, p_mensaje OUT VARCHAR2)
  - BEGIN → SAVEPOINT sp_save
  - Validar que orden existe y no está ya cerrada
  - Validar que todos los servicios tienen ords_total calculado
  - UPDATE Orders SET ord_status = 'CERRADA'
  - COMMIT
  - EXCEPTION WHEN OTHERS THEN ROLLBACK TO sp_save; p_mensaje := SQLERRM; RAISE

#### Función definida por usuario
- **fn_calcular_total_orden**(p_ord_id IN NUMBER) RETURN NUMBER
  - SELECT COALESCE(SUM(ords_total), 0) FROM ServiceOrders WHERE ord_id = p_ord_id
  - Llamada desde SELECT: `SELECT fn_calcular_total_orden(1) FROM dual`

#### Función de permisos
- **fn_tiene_permiso**(p_rol IN VARCHAR2, p_permiso IN NUMBER) RETURN NUMBER
  - Busca en tabla permisos_rol si (permiso_bitmask & p_permiso) = p_permiso
  - RETURN 1 si tiene, 0 si no

#### Trigger
- **trg_set_ses_id** (BEFORE INSERT on each table): asigna `ses_id` desde variable de sesión o contexto
- **trg_validar_cierre_orden** (compound trigger on Orders):
  - BEFORE UPDATE: si ord_status cambia a 'CERRADA', validar que ServiceOrders no tenga filas sin ords_total
  - Si hay servicios sin total, raise application error (manejo de tabla mutante via compound trigger)

#### Seed data
- Sessions, Clients (3), Vehicles (5), Services (4), Orders (3 con ServiceOrders), Users (3: admin, mecanico, recepcion), permisos_rol (4 roles)

#### Usuario BD con privilegios mínimos
- Crear usuario `taller_app` con solo SELECT, INSERT, UPDATE, DELETE en tablas propias + EXECUTE en funciones/SP. Sin DDL ni acceso a esquemas ajenos.

- [ ] Todas las migraciones Alembic ejecutan sin error contra Oracle
- [ ] `sp_cerrar_orden` cierra orden con COMMIT/ROLLBACK + EXCEPTION + OUT param

- [ ] `fn_tiene_permiso` valida bitmask correctamente
- [ ] `vw_resumen_clientes` y `vw_ordenes_activas` devuelven datos
- [ ] Vista materializada `vm_metricas_taller` existe y es refrescable
- [ ] Compound trigger rechaza cierre de orden con servicios sin total
- [ ] Trigger `trg_set_ses_id` asigna ses_id automáticamente en INSERT
- [ ] Seed data inserta datos consistentes (integridad referencial)
- [ ] CHECK constraints rechazan valores inválidos
- [ ] Índice compuesto y funcional creados

- [ ] `ruff check .` pasa en taller-mecanico-api
- [ ] `npm run lint && tsc --noEmit` pasan en auto-hub-pro

## Riesgos y dependencias
- Los objetos PL/SQL requieren ejecución directa contra Oracle (no pasan por Alembic). Usar `op.execute()` en migración Alembic raw.
- Compound trigger es sintaxis Oracle-specific — verificar versión 23ai.
- UUID con RAW(16) requiere cambios en modelos SQLAlchemy (`TypeDecorator` custom).
- El usuario `taller_app` debe crearse con `GRANT CONNECT, RESOURCE` limitado — script separado.
- Seed data depende de que las FK `ses_id` apunten a Sessions existentes.
